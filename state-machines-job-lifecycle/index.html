The life of a film job

From Create to the finished film, through review, cancel, reopen and restart. Before and after.

By Guy Eden

How we got here

1Prompt one: find themFind all of the implicit state machines in my app.Result: 18 found, ranked by risk
2Prompt two: pin it down, then build itVerify each finding against the code. First write tests that pin today's behaviour, including invalid moves, duplicates, retries and crashes. Then make the state explicit, one machine at a time, and keep existing records working.Result: 5 job bugs found and fixed, each with a failing test first
Before

The job's state is scattered, and everyone re-derives it

Many modules write it. 13 different checks work out "what is this job doing" again from different pieces. 7 different rules decide "this run may still write".

The bad moment: a finishing build exits cleanly just as the customer reopens the selection.

The finishing build"Exited fine, so complete"
The reopened run"I'm running again"
The film folder"Renamed under the new run"
The customer sees"Failed", film on disk

Nobody asked who owns the job now. The old run wrote its verdict over the new one.

After

Seven states, and a run only writes while it owns the job

normal finished stops
Donea finished build no longer completes over a reopened run
Donea cut cloud start is ended after 10 minutes, not left on Starting forever
Doneone lock per job, so two cancels at once cannot fail a restored film

class State(str, Enum):
    ABSENT, QUEUED, BUILDING, WAITING, REVIEWING,
    RENDER_QUEUED, RENDERING, REOPENING, COMPLETE, FAILED
Built and merged 2. The legal moves, listed once (41 in all, a few shown)
TRANSITIONS = {
  (State.BUILDING,  Event.REVIEW_READY):       State.REVIEWING,
  (State.REVIEWING, Event.DECIDED):            State.RENDER_QUEUED,
  (State.RENDERING, Event.BUILD_EXITED_OK):    State.COMPLETE,
  (State.RENDERING, Event.CANCELLED):          State.FAILED,
  (State.COMPLETE,  Event.SELECTION_REOPENED): State.REOPENING,
  # ... 36 more
}

def next_state(state, event):
    try:
        return TRANSITIONS[(state, event)]
    except KeyError:
        raise IllegalTransition(f"{state.value} + {event.value}")

A move that is not in the table is illegal. REOPENING + BUILD_EXITED_OK is not in it, and that is the finish-over-reopen bug.

Built and merged 3. One question for the state, instead of 13 checks
def derive_state(facts):
    if facts.state == "complete": return State.COMPLETE
    if facts.state == "failed":   return State.FAILED
    if facts.is_waiting:
        if facts.waiting_for == "film": return State.QUEUED
        return (State.RENDER_QUEUED
                if facts.waiting_for in ("render", "finish")
                else State.WAITING)
    if facts.review_wait:         return State.REVIEWING
    if facts.selection_is_reopened and not facts.decision:
                                  return State.REOPENING
    if facts.decision:            return State.RENDERING
    return State.BUILDING
Built and merged 4. The guard every verdict asks
def run_still_owns_job(*, cancelled, superseded_at, started):
    return not cancelled and not (
        superseded_at is not None and superseded_at >= started)
Not built yet 5. How a caller will write a state change
if not run_still_owns_job(...):

self._transition(job_id, Event.BUILD_EXITED_OK)   # the only writer

Parts 1 to 4 are real code in the repository and are tested against the old behaviour. Part 5 is the next step: the one transition function that refuses an illegal move before writing.

So it does not drift back

One ownerone function is the only place allowed to change a job's state
A table testevery state and event is tried, so a new move must be listed
A commit checka write to job state outside the owner fails the commit

Planned. None of the three is built for the job lifecycle yet.

What changes

Before
  • State lives in a status file, flag files, about 15 records and files that exist or not.
  • Thirteen checks each work out the state their own way.
  • Seven different rules decide whether a run may still write.
After
  • Seven states, written once, with the moves between them.
  • One question before any verdict: does this run still own the job?
  • Existing job records keep their shape, so jobs in flight carry on.

Five guards are built and tested. The seven-state owner is the next step, and it goes in with a failing test first.
