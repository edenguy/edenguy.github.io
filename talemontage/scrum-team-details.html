Fresh session per item, state in the worktree

A long-lived agent re-reads its whole history every turn: the first day's reused reviewer read 414,000 cached tokens a turn over 592 turns; a fresh headless reviewer pays about 13,500 cache-write tokens once. So nothing stays alive between items. The verifier was recycled after four bugs in one session (the session's own report; not a figure the files hold), and the main session is handed over at natural breaks with a HANDOVER_<date>.md.

One item's life

  1. wq add from the main session: a line of open work, queued.
  2. The supervisor sees ready --role planner say yes and starts one headless planner; it reads the code and writes the brief with the files the item owns: specced. Only an item carrying needs_contract goes to the architect first.
  3. ready --role worker says the item is claimable (no live claim owns its files, its prerequisites merged); a worker is started; claim makes C:\dev\tm-<item> on wq/<item>: claimed.
  4. The worker implements and tests there; the pre-commit hook runs its quick gates; the prepare-commit-msg hook writes the token trailer; submit refuses a dirty tree or a file outside the claim: submitted.
  5. Unless the planner graded it low risk, a reviewer is started and reads the diff against the brief: verified, or returned with reasons (the next claimant continues in the same tree).
  6. wq merge (or the supervisor's --merge) tries the branch on main's head in a throwaway tree, merges with --no-ff, then removes the worktree and deletes the branch: merged. The post-merge hook tidies what no queue accounts for; merge_check.py runs after a batch because a merge fires no pre-commit.

One bug's life

  1. A finder (chaos-monkey, bug-prover, or the code reviewer under /cr) queues a scenario.
  2. The test-writer writes the smallest failing test; the pipeline runs it red twice; its hash is recorded and it is immutable from here.
  3. Triage accepts it as proven or marks it invalid or a duplicate. The architect writes the hashed contract, or routes it needs-owner with options; the owner answers through resolve.
  4. The mitigator fixes it in its own tree on fix/<id>, on main's current head, and marks it fixed.
  5. The verifier's verify-run replays the proof red before the fix, green after, red with only the production change taken back, plus the contract's suites: verified, returned or blocked.
  6. bug_queue.py merge merges verified bugs only, each tried on main's head first; the proof is now a regression test and audit notices if it is ever changed.

The trailer, and what it is honest about

Written by ~/.claude/scripts/token_trailer.py through prepare-commit-msg; the settled total goes to ~/.claude/state/token-ledger.jsonl when the agent stops. It is a session token delta, not a causal cost: the window also holds file reads, answers and abandoned attempts. It says provisional because the transcript is appended asynchronously; a merge says not-measured; the workflow (queue, delegated, direct) and the runtime (poll, wait/1) are derived from disk, never declared. 219 commits since 08:00 on 2026-10-21; about 209 carry it. It can never fail a commit.
